# Мониторинг DoH и VPN флота микротиков в Zabbix

English version: [README.md](README.md).

Схема: коллектор на `192.168.31.31` (hp-debian) раз в 2 минуты опрашивает каждый
роутер по SSH и отправляет значения trapper-элементам Zabbix. Сами роутеры ничего
не шлют — на устройстве с `device-mode=home` это невозможно (`fetch` и `scheduler`
там закрыты).

```
192.168.31.31 (hp-debian)
  doh-zabbix-collector.timer  ->  doh-zabbix-collector.service
        |  ssh chateau-md@<роутер>   (ключ /root/.ssh/id_mikrotik_agent)
        v
  RouterOS: :resolve трех канареек + /ip dns get use-doh-server
            + /interface wireguard peers last-handshake
        |
        v  zabbix_sender 127.0.0.1:10051
  Zabbix 8.0 trapper-элементы -> триггеры -> деревья сервисов
```

Замерено по коду этого каталога: 6 устройств, 8 элементов, 5 триггеров,
2 дерева сервисов, таймер на 2 минуты (`OnBootSec=90`, `OnUnitActiveSec=2min`,
`AccuracySec=10s`).

## 1. Устройства

| Хост | Адрес | Роль | Ожидаются пиры VPN |
|---|---|---|---|
| `mt-31-1` | 192.168.31.1 | офис, шлюз (Chateau PRO ax) | да |
| `mt-31-2` | 192.168.31.2 | офис, точка доступа (cAP ax) | нет |
| `mt-31-9` | 192.168.31.9 | тестовый стенд (hAP ax²) | нет |
| `mt-1-1` | 192.168.1.1 | площадка Флотская | да |
| `mt-3-1` | 192.168.3.1 | площадка ILAB | да |
| `mt-4-1` | 192.168.4.1 | площадка Нарвская | да |

Список живёт в `DEVICES` обоих скриптов; списки обязаны совпадать.

## 2. Что снимается

| Ключ элемента | Тип | Смысл |
|---|---|---|
| `doh.state` | число | 0 здоров, 1 пара-заглушка, 2 нет пригодного ответа, 3 нет данных |
| `doh.endpoint` | текст | текущий `/ip dns use-doh-server` |
| `doh.canary` | текст | ответы на `example.com`, `cdnjs.cloudflare.com`, `cdn.tailwindcss.com` |
| `doh.monitor` | число | установлен ли на устройстве скрипт-монитор DoH |
| `vpn.state` | число | 0 ок, 1 деградация, 2 авария, 3 нет данных |
| `vpn.peers` | число | количество пиров wireguard |
| `vpn.handshake` | число (с) | возраст самого свежего рукопожатия |
| `vpn.detail` | текст | пояснение словами |

Классификация DoH повторяет правило самого монитора: пустой ответ, `0.0.0.0` и
префиксы `8.6.112.` / `8.47.69.` считаются непригодными, а набор ответов
называется `stub`, если пара-заглушка присутствует. Коллектор не вводит своих
порогов — список канареек и префиксы заглушки в нём те же, что в
`routeros/05-dns-health-monitor.rsc`.

Классификация VPN: нет пиров — авария; рукопожатий нет больше 900 с (15 минут) —
авария; старше 300 с (5 минут) — деградация; иначе ок. Устройства без туннелей
(`mt-31-2`, `mt-31-9`) всегда ок — туннели им не нужны.

## 3. Триггеры

| Имя | Выражение | Важность |
|---|---|---|
| DoH не работает | `last(/{host}/doh.state)=2` | Disaster |
| Нет данных о состоянии DoH | `nodata(/{host}/doh.state,15m)=1` | Warning |
| VPN-туннель лежит | `last(/{host}/vpn.state)=2` | Disaster |
| VPN-туннель нестабилен | `last(/{host}/vpn.state)=1` | Warning |
| Нет данных о состоянии VPN | `nodata(/{host}/vpn.state,15m)=1` | Warning |

Пять триггеров, все исключающие (`=2`, а не `>=2`): один инцидент открывает одну
проблему, а тихое `0` её закрывает. Выражения процитированы из `TRIGGERS` в
`doh-zabbix-setup.py`.

Триггера «DoH отдаёт пару-заглушку» нет намеренно: коллектор показывает её как
`doh.state=1` и в `doh.canary`, но для части сетей эта пара — штатный ответ
Cloudflare (`docs/troubleshooting.md` §6.10 основного репозитория), и такой триггер
висел бы постоянно.

## 4. Деревья сервисов

```
DoH на микротиках
  ├── DoH на микротиках / mt-31-1     (теги: service=doh, device=mt-31-1)
  ├── … по одному на устройство
VPN                       (бывший «VPN Гжатская», переименовывается скриптом)
  ├── Микротики
        ├── Микротики / mt-31-1       (теги: service=vpn, device=mt-31-1)
        └── … по одному на устройство
```

Два дерева: `DoH на микротиках` и `VPN` → `Микротики`, в каждом по листу на роутер.
Листья несут метки проблем, родители их агрегируют.

Правила Zabbix 8.0, на которые пришлось наткнуться:

* у сервиса не может быть одновременно `problem_tags` и детей — родитель
  агрегирует детей, лист получает статус по меткам;
* агрегация родителей работает только при `algorithm=2` («проблема, если хотя бы
  у одного ребёнка»); при `algorithm=1` авария ребёнка наверх не поднимается;
* статус сервиса `-1` в API — это **OK**, а не «нет данных»; проверять аварию надо
  по `status>=1`;
* в API удалены `parentid` и параметр `auth` в JSON-RPC: токен идёт заголовком
  `Authorization`, иерархия — массивом `parents`;
* подписи значений (`valuemap`) принадлежат хосту, общих в Zabbix 8 нет.

## 5. Установка с нуля

```bash
# 1. объекты в Zabbix (идемпотентно: существующие хосты ищутся по адресу
#    интерфейса, свои прежние хосты-дубли удаляются)
export ZBX_USER=... ZBX_PASSWORD=...        # логин API, в файле его нет
python3 doh-zabbix-setup.py

# 2. коллектор и таймер на 192.168.31.31
install -m 755 doh-zabbix-collector.py /usr/local/bin/
# юниты — в репозитории: systemd/doh-zabbix-collector.{service,timer}
systemctl daemon-reload && systemctl enable --now doh-zabbix-collector.timer

# 3. проверка
systemctl list-timers doh-zabbix-collector.timer
journalctl -u doh-zabbix-collector.service -n 10
```

Требования на сервере: `zabbix_sender` (`/usr/local/bin/zabbix_sender`), ключ
`/root/.ssh/id_mikrotik_agent` с доступом `chateau-md@` на каждый роутер,
в `known_hosts` — актуальные ключи хостов (иначе ssh откажет).

Учётные данные в репозитории **не хранятся**: `doh-zabbix-setup.py` берёт логин и
пароль API из переменных окружения `ZBX_USER` / `ZBX_PASSWORD` и останавливается с
понятным сообщением, если их нет. Литерал в этом файле был дефектом — см.
`SECURITY.md` основного репозитория.

## 6. Проверка, что мониторинг живой

```bash
# значения доходят
printf '"mt-31-1" vpn.state "0"\n' | zabbix_sender -z 127.0.0.1 -i -

# срабатывание и восстановление (таймер на время проверки остановить,
# иначе он перезапишет значение через 2 минуты)
systemctl stop doh-zabbix-collector.timer
printf '"mt-31-1" vpn.state "2"\n' | zabbix_sender -z 127.0.0.1 -i -
# в Zabbix: проблема «VPN-туннель лежит», сервис mt-31-1 -> авария ->
#           «Микротики» -> «VPN»
printf '"mt-31-1" vpn.state "0"\n' | zabbix_sender -z 127.0.0.1 -i -
systemctl start doh-zabbix-collector.timer
```

Проверено 26.10.2026: событие `ПРОБЛЕМА` в 14:25:23, `закрыто` в 14:25:27;
агрегация ребёнок → «Микротики» → «VPN» подтверждена.
